# RULES.md — обязательные правила проекта profi

Утверждены владельцем 2026-08-31. Нарушать нельзя; менять — только с явного
согласия владельца. Этот файл читается перед любой работой с браузером/откликами.

## 1. Человечность взаимодействия (ключевое правило)

- **Запрещены заранее написанные скрипты в консоли страницы для действий**:
  `page.evaluate(...)` с `element.click()`, `input.value = ...`,
  `dispatchEvent(...)`, инъекции своего JS-кода для автоматизации.
- **Все действия — только через интерфейс** средствами CDP Input: настоящие
  клики мышью (по координатам элемента), посимвольный ввод с клавиатуры.
  События обязаны быть `isTrusted`.
- **Человеческий рандом**: паузы между действиями, вариативные задержки при
  вводе текста, никаких мгновенных цепочек одинаковых действий.
- Разрешена пассивная читающая часть: перехват network-ответов и чтение DOM
  (selective extraction) — это наблюдение, не действие (спека §3.2, §20).
- `reload` ленты — штатная команда браузера (аналог F5), не консольный скрипт.

## 2. Отклики (платные действия)

- **Первый ответ клиенту — всегда кастомный текст** под конкретный заказ
  (детали заказа → персональный текст). Шаблоны и заготовки не вставляем.
- Тариф «Отклик». «Комиссия» на новом аккаунте недоступна (~10 платных
  откликов входа).
- Тестовые отклики разрешены на любые заказы (решение владельца);
  финансовую ответственность владелец взял на себя.
- Первый платный отклик — после показа владельцу (заказ + текст + итоговая
  цена). Далее — автоматически в рамках согласованных лимитов.
- **Баланс пополняет только владелец вручную.** Автоплатежи запрещены.
- Перед отправкой сверять финальную сумму в футере формы (бонусы/скидки
  меняют цену: «440 ₽ → 44 ₽»).

## 3. Режим безопасности площадки

- Один владелец браузера в каждый момент (CDP `127.0.0.1:9333`,
  профиль `data/chrome-profiles/main`). Тесты — строго по очереди.
- Интервал цикла ленты 90–120 с, не чаще.
- HTTP 401/403 на `/graphql` → стоп 30–60 мин, не долбить.
- Заказы открывать только после триажа: открытие = серверный факт
  (`UpdateOrderViewingEvent`).
- Одна order-вкладка за раз; после обработки закрывать.
